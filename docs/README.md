# 工程文档索引

本目录保存可追溯的工程记录。根目录的 [changelog.md](../changelog.md) 是版本入口；本文件解释文档分类、命名和维护规则。

## 目录结构

| 目录 | 记录类型 | 负责回答的问题 |
| --- | --- | --- |
| `incidents/` | 事故/缺陷复盘 | 发生了什么、影响多大、根因是什么、如何处置 |
| `adr/` | 架构决策记录 | 为什么这样修、否决了哪些替代方案、后果是什么 |
| `verification/` | 验证记录 | 如何复现、实际结果、哪些仍未验证 |
| `releases/` | 版本说明 | 每个版本给使用者带来了什么变化 |
| `development/` | AI 辅助开发溯源 | 使用了什么模型、Harness、工具和提示约束 |

## 标识规范

| 类型 | 格式 | 示例 |
| --- | --- | --- |
| 事故 | `INC-YYYY-NNN` | `INC-2026-001` |
| 架构决策 | `ADR-NNNN` | `ADR-0001` |
| 验证 | `VER-YYYY-NNN` | `VER-2026-001` |
| 版本 | SemVer + Git tag | `v1.0.1` |

## 记录关系

```text
INC (事实与根因)
  └─ ADR (修复决策)
       └─ VER (验证证据)
            └─ Release (对外说明)
                 └─ changelog.md (版本索引)
```

## 维护规则

1. 事故记录以事实和证据为主；新增发现使用“补充”日期，不覆盖原始结论。
2. ADR 记录当时可见的信息和取舍；后续决策另立 ADR，并写明取代关系。
3. 验证记录必须区分“现场实测”“代码级检查”“未验证”。不得把未执行的项目写成通过。
4. 发布说明面向使用者，不复述完整事故分析。
5. AI 开发记录保留可复现的版本、提示摘要和工具链，不记录 API 密钥、账户令牌或模型内部推理。
6. 文档之间使用相对链接，保证在 GitHub 和本地 Markdown 阅读器中都可访问。
